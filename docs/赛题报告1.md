# 集创赛“华强 x 昇腾”智能视觉交互系统设计与实现报告

## 摘要

本项目面向全国大学生集成电路创新创业大赛“华强 x 昇腾”命题赛道，围绕主题乐园、展演场馆和互动大屏等开放式文旅场景，设计并实现了一套基于 **PYNQ-Z2 FPGA + 华为昇腾 Ascend 310B NPU** 的智能视觉交互终端系统。系统通过视频采集与预处理、端侧姿态识别、表情识别、多目标交互决策、后端事件分发和卡通熊 IP 视频联动，实现了“游客动作/表情输入—AI 推理判断—互动事件生成—IP 视频反馈”的完整闭环。

在硬件架构上，PYNQ-Z2 侧负责视频采集、基础 ISP、ROI、缩放和 UDP 分片发送；Ascend 310B 侧负责接收 ROI/视频数据，使用 AscendCL 完成模型加载与推理调度，并执行姿态识别、表情识别和事件输出；PC/后端侧通过 WebSocket 服务完成互动事件分发，驱动熊二卡通形象视频播放与剧情状态切换。在算法实现上，系统采用 YOLOv26n/s-Pose 完成挥手、比心、欢呼等动作识别，采用 YuNet 人脸检测与 MobileNetV3-Small 表情分类网络完成高兴、惊讶、生气、恐惧、悲伤和中性 6 类表情识别，并通过滑动窗口平滑、动作防抖和剧情状态机提升交互稳定性。

目前，项目已完成姿态识别、表情识别、IP 视频联动、PYNQ 到 310B 再到 PC 的 UDP 链路、WebSocket 后端事件分发、一键启动脚本和本地模拟联调。角色语音对话模块已完成 ASR、LLM、TTS 单模块接入，正在推进 ASR → LLM → TTS 的端到端联调。下一阶段重点为真实硬件端到端性能压测、开放场景鲁棒性优化、日志与异常恢复机制完善，以及语音对话与 IP 联动的深度集成。

**关键词**：Ascend 310B；PYNQ-Z2；FPGA；姿态识别；表情识别；智能视觉交互；IP 联动；WebSocket

## 一、项目概述

### 1.1 项目名称

**华强 x 昇腾智能视觉交互终端系统**

### 1.2 参赛赛题

全国大学生集成电路创新创业大赛“华强 x 昇腾”命题赛道。

### 1.3 应用场景

本系统面向主题乐园、展演场馆、互动大屏和文旅沉浸式体验空间。游客站在摄像头前做出挥手、比心、欢呼等互动动作，或表现出高兴、惊讶等表情后，系统实时识别游客状态，并触发熊二卡通形象的对应互动视频、剧情状态切换和后续语音回应。系统目标是提升游客与虚拟 IP 之间的实时互动体验，使传统单向播放式演艺升级为可感知、可反馈、可扩展的智能互动演艺系统。

### 1.4 项目总体目标

本项目的总体目标是构建一套可在边缘端运行的智能视觉交互终端，实现以下能力：

1. 基于 PYNQ-Z2 FPGA 完成视频采集、基础预处理和 UDP 数据发送；
2. 基于 Ascend 310B 完成动作识别、表情识别和推理事件输出；
3. 支持挥手、比心、欢呼等常见互动动作识别；
4. 支持高兴、惊讶、生气、恐惧、悲伤、中性 6 类表情识别；
5. 支持多目标管理、动作防抖和剧情状态机决策；
6. 支持熊二卡通形象的待机、挥手、比心、欢呼和表情回应视频联动；
7. 支持 UDP 视频/控制链路与 WebSocket 事件分发；
8. 扩展 ASR + LLM + TTS 角色语音对话能力，实现多模态交互。

|---|---|---|

### 2.2 设计约束

1. **实时性约束**：互动系统需要在游客动作或表情出现后快速反馈，整体链路应尽量减少图像处理、模型推理和事件分发延迟。
2. **边缘部署约束**：系统需要运行在 Ascend 310B 等边缘计算平台上，模型和预处理流程应轻量化，避免对 CPU 造成过高负载。
3. **开放环境约束**：乐园场景可能存在光照变化、多人同框、遮挡、背景运动和游客动作不标准等问题，算法需要具备一定鲁棒性。
4. **展示稳定性约束**：比赛现场演示要求系统能够稳定启动、稳定播放、稳定触发，避免误触发、频繁切换、黑屏或卡顿。
5. **扩展性约束**：IP 互动内容应方便扩展，后续能够接入更多角色视频、语音对话、剧情分支和多屏互动。

## 三、系统总体方案

### 3.1 总体架构

系统采用“FPGA 前端预处理 + 310B 端侧推理 + 后端事件分发 + IP 视频联动”的分层架构。各层职责清晰，便于调试、部署和扩展。

```text
摄像头/视频源
    │
    ▼
PYNQ-Z2 FPGA 前端预处理
视频采集、ROI、ISP、缩放、格式处理、UDP 分片发送
    │
    ▼
Ascend 310B 推理与事件生成
UDP 接收、AscendCL 推理、姿态识别、表情识别、动作/表情事件输出
    │
    ▼
后端事件分发与剧情状态机
WebSocket 服务、事件融合、动作防抖、欢呼累计、视频控制指令
    │
    ▼
IP 演艺表现层
熊二待机/挥手/比心/欢呼/表情回应视频播放，无缝切换并回到待机状态
```

### 3.2 系统模块划分

| 模块 | 所在端 | 主要功能 | 当前状态 |
|---|---|---|---|
| 视频采集与基础预处理 | PYNQ-Z2 | 采集视频，执行 ROI、ISP、缩放等处理 | 已具备 HLS 工程基础 |
| UDP 分片通信 | PYNQ/310B/PC | 视频流发送、接收和控制透传 | 已具备三端链路 |
| 姿态识别 | Ascend 310B | YOLOv26n/s-Pose 推理，关键点解码 | 已完成 |
| 动作分类 | Ascend 310B | 挥手、比心、欢呼动作判定 | 已完成 |
| 表情识别 | Ascend 310B/PC 侧系统 | YuNet 人脸检测 + MobileNetV3-Small 分类 | 已完成 |
| 后端服务 | PC/服务端 | WebSocket 事件分发、剧情状态管理 | 已完成 |
| IP 视频播放器 | PC/展示端 | 熊二互动视频播放与无缝切换 | 已完成 |
| 角色语音对话 | PC/服务端 | ASR + LLM + TTS 语音交互 | 进行中 |

### 3.3 数据流与控制流

系统内部包含三类主要数据：

1. **视频数据流**：PYNQ-Z2 或本地视频源将图像帧送入处理链路，经预处理后输入 310B 推理端或 PC 展示端。
2. **推理结果流**：310B 或智能互动系统输出结构化识别结果，包括帧号、时间戳、动作类别、表情类别和置信度。
3. **互动控制流**：后端状态机根据推理结果生成视频切换事件，通过 WebSocket 推送给播放器，驱动 IP 视频联动。

这种设计将像素级处理、AI 推理和表现层播放解耦，使系统既能满足比赛演示需求，也便于后续扩展到多角色、多屏幕或语音交互场景。

## 四、硬件平台与软硬件协同设计

### 4.1 PYNQ-Z2 侧设计

PYNQ-Z2 搭载 Xilinx Zynq-7020 器件，包含 ARM 处理系统和 FPGA 可编程逻辑。本项目中 PYNQ-Z2 侧定位为视频前端处理模块，主要承担：

1. **视频采集**：接收摄像头、HDMI 或其他视频源输入；
2. **基础 ISP**：对输入图像进行白平衡、Gamma 校正和简易降噪等处理；
3. **ROI 处理**：裁剪或筛选感兴趣区域，减少无效背景对推理的干扰；
4. **缩放与格式处理**：将输入图像调整到后续模型或通信链路所需尺寸与格式；
5. **UDP 发送**：将处理后的 ROI 或视频帧通过 UDP 分片发送到 310B 或 PC 端。

PYNQ 侧的设计意义在于将高频像素处理前移，降低 310B 和 CPU 侧预处理压力，同时为后续多路视频融合输入和低延迟处理提供硬件基础。

### 4.2 Ascend 310B 侧设计

Ascend 310B 是系统的核心 AI 推理平台。本项目在 310B 侧完成模型加载、推理调度、姿态识别、动作分类和结果输出，主要包含：

1. **UDP 数据接收**：接收来自 PYNQ 的 ROI 包或视频数据；
2. **AscendCL 推理流程**：完成模型加载、输入输出内存管理和推理执行；
3. **姿态识别模型**：集成 `yolo26s-pose.om`，输出人体关键点；
4. **动作规则判断**：根据关键点坐标和置信度判断挥手、欢呼、比心等动作；
5. **结果发送**：将识别结果以 JSON 格式发送至 PC 或后端服务；
6. **AIPP/DVPP 预处理预留**：为 YUV420SP_U8 输入、640×640 模型尺寸和硬件预处理适配提供基础。

当前 310B 主工程已完成主程序骨架、姿态 ROI 协议头、CMake 构建配置、aarch64 工具链配置、Ascend 环境加载和 AIPP 静态配置占位文件，并已成功生成 `ascend310b_pose` 可执行文件。

### 4.3 DVPP 与 AIPP 加速思路

为减少 CPU 像素处理开销，系统规划使用 310B 的 DVPP 与 AIPP 能力进行硬件预处理：

1. **DVPP**：用于图像缩放、裁剪、格式转换等物理整形操作，将输入帧快速整理为模型需要的固定尺寸。
2. **AIPP**：用于 YUV/RGB 转换、均值减法、归一化、通道重排等数学预处理，使预处理过程与模型推理深度结合。
3. **CPU 调度**：CPU 主要负责数据流控制、模型调用、后处理和事件逻辑，不承担大规模像素遍历。

当前模型输入约束为 **YUV420SP_U8（NV12）**，固定输入尺寸为 **640×640**。后续需要根据最终模型的通道顺序、均值方差和格式要求进一步细化 AIPP 配置。

### 4.4 通信链路设计

系统采用 UDP 和 WebSocket 组合通信：

1. **UDP 链路**：用于 PYNQ → 310B → PC 的视频/ROI 数据传输和控制透传，强调低延迟和实时性；
2. **WebSocket 链路**：用于后端向播放器推送动作、表情和剧情事件，便于与 Python 播放器、Web 前端或其他展示端对接；
3. **分离式端口设计**：视频流、控制流和推理结果流使用不同端口，降低调试复杂度。

默认网络参数如下：

| 参数 | 值 | 说明 |
|---|---|---|
| PC_IP | 192.168.137.1 | PC 端 IP |
| ASCEND_310B_IP | 192.168.2.2 | 310B 接收 IP |
| ASCEND_310B_PC_IP | 192.168.137.100 | 310B 发送 IP |
| PYNQ_IP | 192.168.2.99 | PYNQ 端 IP |
| PC_PORT | 5555 | PC 接收端口 |
| PYNQ_PORT | 9090 | PYNQ/310B 通信相关端口 |
| RESULT_PORT | 5566 | 推理结果返回端口 |

## 五、核心算法与交互逻辑

### 5.1 姿态识别与动作分类

系统采用 YOLOv26n/s-Pose 完成人体关键点检测。与直接使用整图动作分类相比，关键点方案更轻量、更可解释，也更适合比赛现场调试。系统根据手腕、肩部、肘部和胸腔区域之间的空间关系完成动作判断。

动作输出协议如下：

```json
{
  "frame_id": 12345,
  "timestamp_ms": 1712345678901,
  "kps_conf_mean": 0.8523,
  "action_flag": 1,
  "action_conf": 0.9124
}
```

动作类别定义如下：

| action_flag | 动作类别 | 判定逻辑 |
|---|---|---|
| 0 | 未知/无有效动作 | 未满足动作条件或关键点置信度不足 |
| 1 | 挥手 | 单手手腕高于肩部 |
| 2 | 欢呼 | 双手手腕同时高于肩部 |
| 3 | 比心 | 双腕靠拢且位于胸前区域 |

为避免单帧抖动造成误触发，系统在事件层加入连续帧判断、置信度筛选和冷却时间机制。

### 5.2 表情识别

表情识别采用两段式级联方案：先检测人脸，再对人脸 ROI 进行表情分类。

1. **人脸检测**：YuNet；
2. **表情分类**：MobileNetV3-Small；
3. **表情类别**：高兴、惊讶、生气、恐惧、悲伤、中性；
4. **结果平滑**：采用 7 帧滑动窗口多数投票，减少单帧误判。

表情类别定义如下：

| 类别值 | 英文标签 | 中文含义 |
|---|---|---|
| 0 | happy | 高兴 |
| 1 | surprised | 惊讶 |
| 2 | angry | 生气 |
| 3 | fear | 恐惧 |
| 4 | sad | 悲伤 |
| 5 | neutral | 中性 |

### 5.3 多目标管理与事件决策

开放场景中可能存在多人同时出现在画面中的情况。为保证 IP 联动稳定，系统设计了多目标管理与事件决策机制：

1. **主目标选择**：优先选择画面中心区域、关键点置信度高、持续出现时间较长的目标；
2. **动作防抖**：动作需要连续若干帧满足条件才生成有效事件；
3. **触发冷却**：同一动作触发后设置冷却时间，避免视频频繁切换；
4. **优先级控制**：欢呼、比心等强互动动作优先级高于普通挥手；
5. **剧情状态机**：欢呼累计 3 次后触发场景切换，使互动从单次反馈扩展为剧情推进。

### 5.4 IP 联动映射

系统将动作和表情识别结果映射为对应的熊二互动视频：

| 输入事件 | 输出表现 | 说明 |
|---|---|---|
| 无动作/无表情事件 | 待机视频 | 熊二默认待机循环 |
| 挥手 | 挥手回应视频 | 游客挥手后角色挥手回应 |
| 比心 | 比心回应视频 | 游客比心后角色做出积极反馈 |
| 欢呼 | 欢呼互动视频 | 游客双手上举后触发热烈回应 |
| happy/surprised 等表情 | 表情回应视频 | 根据表情类别播放对应反馈 |
| 欢呼累计 3 次 | 剧情状态切换 | 推动互动场景进入下一状态 |

当前 IP 联动层已完成视频资产管理、触发逻辑引擎、无缝切换机制、WebSocket 后端事件分发和剧情状态机。

### 5.5 角色语音对话扩展

为进一步增强沉浸感，系统正在推进角色语音对话模块。该模块由三部分组成：

1. **ASR**：使用 FunASR 完成游客语音识别；
2. **LLM**：根据游客语义和角色设定生成回复文本；
3. **TTS**：将回复文本合成为角色语音。

目前 ASR、LLM、TTS 单模块已接入，正在进行端到端流程调试。后续该模块将与视觉事件状态机统一，使系统从“动作/表情触发视频”升级为“动作 + 表情 + 语音”的多模态交互。

### 6.3 构建与运行流程

本系统支持两种运行方式：

1. **智能 IP 互动系统运行方式**：用于比赛演示，启动推理、后端和播放器；
2. **完整 UDP 链路测试方式**：用于验证 PYNQ → 310B → PC 的通信链路。

智能互动系统可以通过 `scripts/launch_pipeline.py` 一键启动推理、后端和播放器；本地联调可使用 `scripts/launch_local_test.py` 模拟事件，验证后端状态机和视频播放器链路。在 310B 侧，进入 `code/ascend_310b` 后激活 `310B` 虚拟环境，并执行 `bash scripts/build.sh` 可构建 `ascend310b_pose`。

对于 PYNQ HLS 综合，Vitis 2025.2.1 环境下推荐使用：

```bash
vitis-run --mode hls --tcl hls/HLS_Proj/ROI_Test/scripts/run_hls.tcl
```

## 九、项目特色与创新点

### 9.1 FPGA + 310B 异构协同

本项目采用 PYNQ-Z2 FPGA 与 Ascend 310B 的异构协同架构。FPGA 负责视频采集和基础预处理，310B 负责神经网络推理和事件生成，后端负责状态机与表现层联动。该架构避免 CPU 承担全部图像处理和推理任务，符合赛题对边缘智能和硬件协同的要求。

### 9.2 可解释的动作识别状态机

系统没有直接采用黑盒动作分类网络，而是利用人体关键点空间关系判断挥手、比心和欢呼动作。该方法计算量低、可解释性强，便于比赛现场调试和动作规则扩展。

### 9.3 轻量化表情识别级联

表情识别采用 YuNet 人脸检测与 MobileNetV3-Small 表情分类相结合的两段式方案，只对人脸 ROI 进行分类，降低了计算量。同时通过 7 帧滑动窗口多数投票减少瞬时误判，增强视频联动稳定性。

### 9.4 事件驱动的 IP 联动框架

AI 推理层只输出动作、表情和置信度等结构化事件，表现层通过 WebSocket 后端和剧情状态机驱动熊二视频切换。这种事件驱动架构使识别模块与表现模块解耦，后续可快速替换视频资产、扩展新角色或接入 Unity/Unreal 等展示端。

### 9.5 多模态交互扩展能力

项目正在集成 ASR + LLM + TTS 角色语音对话。该扩展能够将现有动作和表情交互升级为视觉与语音融合的多模态 IP 互动，使系统更接近真实乐园中的沉浸式智能演艺终端。

## 十、存在问题与改进方向

### 10.1 当前存在问题

1. **真实硬件端到端压测仍需完成**：虽然本地智能互动闭环和模拟联调已完成，但 PYNQ 实时采集、310B 实时推理、PC 播放器实时联动仍需进一步现场验证。
2. **量化指标仍需补充**：动作准确率、表情准确率、端到端延迟、FPS 和稳定运行时间需要通过统一测试脚本统计。
3. **AIPP 配置仍需最终匹配模型**：当前 AIPP 配置仍具有占位性质，需要根据最终模型输入格式、均值方差和通道顺序细化。
4. **异常处理和日志系统需完善**：需要增加断流重连、模型加载失败处理、播放器异常恢复和统一日志记录。
5. **开放场景样本不足**：强光、暗光、多人、遮挡和复杂背景场景需要继续采集样本并调参。
6. **语音对话闭环尚未完全完成**：ASR、LLM、TTS 单模块已接入，但端到端语音互动和视频联动还在调试阶段。

## 十一、总结

本项目围绕“华强 x 昇腾”赛题，完成了一套基于 PYNQ-Z2 FPGA 与 Ascend 310B NPU 的智能视觉交互终端系统设计与实现。系统以主题乐园和展演场馆为应用场景，通过 FPGA 前端预处理、310B 端侧 AI 推理、UDP/WebSocket 通信和熊二卡通形象视频联动，实现了游客动作识别、表情识别、事件分发和 IP 演艺反馈的完整闭环。

当前系统已经完成姿态识别、表情识别、IP 视频联动、WebSocket 后端服务、一键启动、本地模拟联调、UDP 三端通信链路、310B 主工程构建和 PYNQ HLS 综合验证。姿态识别支持挥手、比心和欢呼；表情识别支持高兴、惊讶、生气、恐惧、悲伤和中性；IP 联动支持熊二待机、挥手、比心、欢呼和表情回应视频切换。系统已经具备比赛演示所需的基本工程闭环。

后续工作将聚焦三个方面：第一，完成 PYNQ 实时视频、310B 推理和 PC/IP 播放器的真实硬件端到端压测；第二，补充动作识别准确率、表情识别准确率、端到端延迟和稳定性等量化数据；第三，完成 ASR + LLM + TTS 角色语音对话闭环，使系统从视觉交互扩展为视觉与语音融合的多模态智能 IP 互动终端。

总体而言，本项目已从初步方案推进到可运行、可演示、可扩展的系统原型阶段。通过进一步的性能验证、现场鲁棒性优化和语音交互集成，系统能够更好地满足赛题对平台适配、视觉识别、IP 联动和开放场景适应性的综合要求。
